# Self-Referential Degradation Perception

## 1. 数据处理 (Data Processing)

### 输入数据 (Input Data)

模型基于包含“干预后”（修改路由）和“基线”（原始路由）输出的生成日志进行训练和测试。

- **训练数据**: Wikipedia 生成结果 (`wiki_results_*`)。数量级1500
- **测试数据**: MT-Bench 生成结果 (`mtbench_results_*`)。数量级1500

### 标签策略：截断式清洗 (Labeling Strategy)

我们的目标是检测干预导致质量下降的第一个分歧点。

1. **原因**：正是因为它的特征像正样本（低熵、高自信），但标签是负样本（Label 0），它构成了机器学习中最讨厌的Label Noise（标签噪声）。
2. **对比**: 逐个 Token 对比 `intervention["output"]` 和 `baseline["output"]` 的序列。
3. **定位截断点**: 找到两个序列出现不同的第一个索引位置 (Cutoff Index)。
4. **标签分配**:
   - **截断点之前的步骤**: 标记为 `1.0` (接受/Good)。
   - **截断点处的步骤**: 标记为 `0.0` (拒绝/Bad，即第一个错误)。
   - **截断点之后的步骤**: 全部丢弃 (防止模型学习已偏离的噪声状态)。

### 特征工程 (Feature Engineering)（考虑计算复杂度）

为每个生成步骤提取一个 **14 维特征向量**，涵盖路由行为、模型置信度和历史状态。

| 特征组       | ID   | 特征名称           | 描述                                 |
| :----------- | :--- | :----------------- | :----------------------------------- |
| **路由信号** | 0    | `curr_score_loss`  | 因路由变更导致的原始专家权重损失量。 |
|              | 1    | `replace_rate`     | 当前步骤中被替换的专家比例。         |
|              | 2    | `max_layer_loss`   | 单层中观察到的最大权重损失。         |
|              | 3    | `accum_score_loss` | 序列累积的分数损失 (归一化)。        |
| **困惑信号** | 5    | `top1_prob`        | Top-1 预测 Token 的概率。            |
|              | 6    | `entropy`          | Top-K Logits 分布的熵。              |
|              | 7    | `margin`           | Top-1 和 Top-2 概率之差。            |
| **历史信号** | 8    | `step_idx`         | 归一化的当前步数索引。               |
|              | 9    | `min_top1_prob`    | 序列至今观察到的最低置信度。         |
|              | 10   | `avg_entropy`      | 序列历史平均熵。                     |
|              | 11   | `hidden_norm`      | 最终隐藏层 Embedding 的 L2 范数。    |
|              | 12   | `prev_mlp_pred`    | 上一步骤的模型预测值。               |

## 2. 模型架构 (Model Architecture)

模型采用轻量级的 **多层感知机 (MLP)**，旨在实现生成过程中的低延迟推理。

### 网络结构

- **输入层**: 12 个特征
- **隐藏层 1**: Linear(14 $\to$ 64) $\to$ ReLU $\to$ LayerNorm
- **隐藏层 2**: Linear(64 $\to$ 32) $\to$ ReLU
- **输出层**: Linear(32 $\to$ 1) $\to$ Sigmoid
- **输出含义**: 当前步骤是“安全”(Accept) 的概率。

### 训练配置

- **损失函数**: `FocalLoss` (Alpha=0.8, Gamma=2.0)，用于解决正负样本不平衡问题 (错误样本远少于正确样本)。
- **优化器**: AdamW (LR=1e-3, Weight Decay=1e-4)。
- **批次大小**: 512。
- **轮次**: 30 (基于验证集 AUC 进行早停)。

# SRDP 实验结果总结报告

## 1. 结果分析

本次实验共进行了 6 轮主要迭代，针对 Loss 函数、样本权重分配以及推理阈值策略进行了多维度的优化与测试。以下是各实验阶段的详细分析：

*   **Baseline (run_20260125_235815)**
    *   **策略**: 初始基准模型。
    *   **结果**: 模型倾向于“高召回”策略，Recall 达到极高的 **99.99%**，但 Precision (94.25%) 和 AUC (0.8995) 相对较低。这意味着模型极少漏掉目标，但区分度有待提升。

*   **负样本加权 (run_20260126_001026)**
    *   **策略**: 显著增加负样本（坏 Token）的权重 (Weight=20.0)，旨在提升模型对坏 Token 的拦截能力。
    *   **结果**: Precision 提升至 **99.64%**，表明误报（将坏判为好）极少。但代价是 Recall 大幅下跌至 73.23%，Accuracy 降至 74.53%，说明模型变得过于保守，误伤了大量正常 Token。

*   **Focal Loss + Accuracy 寻优 (run_20260126_003220)**
    *   **策略**: 引入 Focal Loss 以解决样本不平衡问题，并以 Accuracy 为指标选取最佳阈值。
    *   **结果**: 整体表现回归 Baseline 水平，Recall 维持在 100%，AUC 略微提升至 0.9124。Focal Loss 在此场景下未带来显著的质变，但维持了高召回特性。

*   **Specificity 优先 (run_20260126_003917)**
    *   **策略**: 极端测试，以 Specificity (特异度/拦截率) 为核心指标选取阈值。
    *   **结果**: 虽然实现了 **100% Precision**，但 Recall 暴跌至 41.10%，Accuracy 仅 44.49%。尽管 AUC 达到 0.9226（显示模型潜力不错），但该阈值策略不可用。

*   **F1 Score 优先 (run_20260126_004444)**
    *   **策略**: 使用 **F1 Score** 作为自动寻优指标 (Best Threshold: 0.55)。
    *   **结果**: 取得了综合性能的最佳平衡。Accuracy 达到全场最高的 **94.31%**，F1 Score 达到 **0.9706**。Precision (94.46%) 和 Recall (99.81%) 均保持在很高水平。

*   **阈值敏感度分析与推荐 (run_20260126_004717)**
    *   **策略**: 在保持模型不变的基础上，详细扫描不同阈值下的指标变化，寻找“拦截率”与“召回率”的最佳折衷点。
    *   **结果**: 推荐最佳阈值为 **0.65**。在此阈值下，模型在保证 **98.25%** 高 Precision 的前提下，仍能维持 **88.13%** 的 Recall。相比纯 F1 策略，该方案更侧重于**安全性**（更高的 Precision）。

## 2. 结果对比

下表汇总了各次实验在 MT-Bench 测试集上的核心指标对比：

| 实验 ID        | 策略描述                       | Accuracy   | AUC        | Precision  | Recall     | F1 Score   | 评价                     |
| :------------- | :----------------------------- | :--------- | :--------- | :--------- | :--------- | :--------- | :----------------------- |
| **run_235815** | Baseline                       | 94.24%     | 0.8995     | 94.25%     | **99.99%** | 0.9704     | 初始基准，高召回         |
| **run_001026** | 负样本加权 (W=20)              | 74.53%     | 0.9095     | **99.64%** | 73.23%     | 0.8442     | 极高精确，低召回，误伤多 |
| **run_003220** | Focal Loss (Acc优先)           | 94.23%     | 0.9124     | 94.23%     | 100.00%    | 0.9703     | 性能持平基准             |
| **run_003917** | Focal Loss Specificity 优先    | 44.49%     | **0.9226** | 100.00%    | 41.10%     | 0.5825     | 阈值过严，不可用         |
| **run_004444** | **Focal Loss F1 Score 优先**   | **94.31%** | 0.9105     | 94.46%     | 99.81%     | **0.9706** | **综合指标最佳 (推荐)**  |
| **run_004717** | **Focal Loss 阈值扫描 (0.65)** | 87.34%     | 0.9171     | 98.25%     | 88.13%     | 0.9292     | **最佳平衡 (安全侧重)**  |

### 总结

1. **综合最优**: 若追求整体性能，**run_004444 (F1 Score 优先)** 是最佳选择，各项指标最为均衡。

2. **安全优先**: 若应用场景对“误放行坏 Token”极其敏感，建议采用 **run_004717** 推荐的 **0.65 阈值**。该设置牺牲了部分召回率（~12%），换取了更高的精确率（98.25%），适合对安全性要求更高的场景。

# SRDP 软标签 (Soft Label) 实验结果总结报告

## 1. 结果分析

本次软标签实验共进行了 5 轮主要迭代，重点探索了不同的 Loss 优化目标（MSE, AUC, MAE）以及负样本权重对软标签回归模型性能的影响。软标签实验的核心在于预测连续值（如接受率或置信度），而非简单的 0/1 分类。

以下是各实验阶段的详细分析：

*   **Baseline (AUC 优化) (run_soft_20260128_230452)**
    *   **策略**: 使用 **AUC** 作为主要优化指标进行训练。
    *   **结果**: 模型表现出极高的 Precision (**99.85%**)，说明模型非常谨慎，几乎不产生误报。但 Recall (80.17%) 和 Accuracy (80.19%) 相对一般。MAE 为 0.1255。这表明以 AUC 为导向会使模型倾向于对高置信度样本进行正确排序，但在绝对值的回归准确性上可能不是最优。

*   **MSE 优化 (最佳软标签模型) (run_soft_20260128_231323)**
    *   **策略**: 改用 **MSE (均方误差)** 作为核心优化目标，直接拟合软标签数值。
    *   **结果**: 取得了软标签系列实验中的**最佳综合表现**。
        *   **AUC**: 提升至 **0.8973**，优于 Baseline。
        *   **Precision**: 维持在极高的 **99.86%**。
        *   **Recall & Accuracy**: 分别提升至 **82.60%** 和 **82.61%**。
        *   **F1 Score**: 突破 0.9 大关，达到 **0.9041**。
        *   **结论**: 直接优化 MSE 能更有效地学习软标签分布，从而提升整体分类性能。

*   **预测值缩放 (run_soft_20260131_095031)**
    *   **策略**: 尝试将预测值放大 10 倍 (**10) 后再进行预测/计算 Loss，试图放大梯度信号。
    *   **结果**: 实验失败。虽然 Precision (99.76%) 依然很高，且 F1 (0.9204) 和 Recall (85.43%) 看似提升，但 **MSE (0.0739)** 和 **MAE (0.2523)** 显著恶化，说明模型对真实值的拟合能力大幅下降。AUC (0.8821) 也出现了退步。这种非线性的缩放破坏了软标签的物理意义。

*   **负样本加权 (run_soft_20260131_104549)**
    *   **策略**: 在软标签训练中引入**负样本加权 (10倍)**，旨在强迫模型关注负样本（坏 Case）。
    *   **结果**: 极度偏科。虽然 MSE 降至全场最低的 **0.008968**（看似拟合很好），但 **AUC 暴跌至 0.6136**，Recall 和 Accuracy 也仅为 **59.46%**。模型可能过拟合了负样本的低分值，导致整体排序能力完全丧失，无法有效区分正负样本。

*   **标准 MSE + 负样本置零 (run_soft_20260131_155848)**
    *   **策略**: 回归标准 MSE Loss，不进行加权，但显式地将负样本的 Label 设为 0（硬性截断）。
    *   **结果**: 性能稳健，接近最佳模型。Accuracy (**83.62%**) 和 Recall (**84.40%**) 甚至略高于最佳模型，但 AUC (**0.8825**) 和 Precision (**97.93%**) 稍有回落。这表明“负样本置零”策略能提升召回率，但牺牲了一定的排序质量（AUC）和精确度。

## 2. 结果对比

下表汇总了各次软标签实验在 MT-Bench 测试集上的核心指标对比：

| 实验 ID        | 策略描述           | Accuracy   | AUC        | Precision  | Recall     | F1 Score   | MSE (Target) | 评价                |
| :------------- | :----------------- | :--------- | :--------- | :--------- | :--------- | :--------- | :----------- | :------------------ |
| **run_230452** | Baseline (AUC优化) | 80.19%     | 0.8935     | 99.85%     | 80.17%     | 0.8893     | 0.1255 (MAE) | 高精低召，基准水平  |
| **run_231323** | **MSE 优化**       | 82.61%     | **0.8973** | **99.86%** | 82.60%     | 0.9041     | 0.0199       | **综合最佳 (推荐)** |
| **run_095031** | 预测值缩放 (*10)   | **85.33%** | 0.8821     | 99.76%     | **85.43%** | **0.9204** | 0.0739       | 拟合误差大，AUC下降 |

### 总结与建议

1.  **首选策略**: **run_231323 (MSE 优化)** 是目前软标签路径下的最优解。它在保持极高 Precision (99.86%) 的同时，实现了最高的 AUC (0.8973)，证明**直接、纯粹的 MSE 回归**最适合处理此类软标签任务。
2.  **避免过度工程**: 复杂的技巧如“预测值缩放”或“强负样本加权”在软标签场景下反而带来了副作用（AUC 下降或模型崩溃）。
3.  **对比硬标签**: 相比于硬标签的最佳结果 (F1 ~0.97, Acc ~94%)，目前的软标签最佳结果 (F1 ~0.90, Acc ~82%) 仍有差距。软标签虽然提供了更丰富的信息，但在最终的二分类决策边界上可能不如专门优化的硬标签模型锐利。
