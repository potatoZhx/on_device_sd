# draft 停止

### 1. 基于路由置信度与专家相似度 (Routing-based)

- 专家偏差累积（Routing Divergence）： 但是专家参数量大，相似度可能没什么区分度

  计算 Draft 阶段选择的替代专家（GPU 专家）与原本路由预测的专家（本应在 CPU 上的专家）之间的表征相似度（Cosine Similarity）。 

  - 如果连续几个 token 选中的替代专家与原始专家极其不匹配，说明误差正在迅速累积，应立即停止 Draft。

- 路由分数边际（Routing Margin）：

  观察 Top-1 和 Top-2 专家的得分差值。如果差值很小，说明模型本身就在犹豫，此时用“替代专家”产生错误的概率极高，建议提早验证。

### 2. 基于序列信息熵与衰减模型 (Entropy-based)

- Token 熵值监控：

  不需要计算全量 Logits 的信息熵。只取 Top-5 的 Logits 进行归一化计算。当 Entropy(Draft_Next_Token) 突增时，意味着模型预测进入了不确定区，通常是 Draft 失败的信号。

- 线性概率衰减（Decay Heuristic）：

  根据历史平均接受率 $E[\alpha]$，设定一个长度 $L$ 的衰减函数。例如，第 $n$ 个 token 的继续概率为 $P(continue) = \alpha^n$。当 $P < \tau$（阈值）时停止。



### 1. 方案思路：基于“累计置信度损失”的衰减策略

不要只看单步的接受概率，而要看**累计误差**。

- **公式构思**：定义一个 $Confidence\_Score = \sum_{t=1}^{n} \log(P_{accept, t})$。
- 每一步 $P_{accept, t}$ 由“路由距离”和“Token 熵”加权决定。当累计得分低于阈值 $\tau$ 时，立即切入验证。

### 2. 方案思路：基于“专家忠实度”的判定

如果 MoE 的 Router 强行要求调用 CPU 专家，但你用了一个分值极低的 GPU 专家替代，这种“强行替代”的偏差远大于“Router 本身犹豫不决”的偏差。

- **建议指标**：计算 $Score_{original\_top1} / Score_{substituted}$。比例越高，说明替代专家的质量越差，Draft 应越早停止。

### 3. 实验细节建议

- **预热实验**：先进行一次 Static Analysis，记录在不同“专家替换率”下，Token 接受率的统计分布。这将为你设定初始阈值提供数据支撑。

- 关键对比指标：引入 “有效 Token 产出率（Efficiency per Step）”。

  

  $$Efficiency = \frac{E[Acceptance\_Length] \times GPU\_Verify\_Time}{Total\_Draft\_Time + Total\_Verify\_Time}$$

  

  你的动态策略目标应该是最大化这个比值，而不是单纯提高接受率。



## 1. 算法逻辑设计：基于“累积可靠度评分”的启发式公式

我们设计一个轻量级的 **累积可靠度评分（Cumulative Reliability Score, CRS）** 机制。该机制在 Draft 序列的每一步 $t$ 计算一个即时分值 $s_t$，并结合历史衰减，决定是否停止。

### 核心判定公式

$$Score_t = \gamma \cdot Score_{t-1} + (1 - \gamma) \cdot \Phi(E_t)$$



当 $Score_t < \tau$（阈值）时，立即停止 Draft。

### 即时评分函数 $\Phi(E_t)$ 设计

考虑到性能，我们优先选择 专家级特征，因为它们在路由阶段即可获得，无需等待 Logits 生成：



$$\Phi(E_t) = \frac{\sum_{i \in \text{Selected\_on\_GPU}} w_i}{\sum_{j \in \text{All\_Selected}} w_j} \cdot (1 - \text{H}_{norm})$$

- **$w_i$**：路由预测的专家权重。如果 Top-K 专家中最重要的（权重最大的）不在 GPU 上，分值会迅速下降。
- **$\text{H}_{norm}$**：归一化的路由分布熵。熵越高，代表模型对专家的选择越“犹豫”，此时替换专家的风险相对较低；熵越低且 Top-1 缺失，风险极高。

------

## 2. 阈值自适应机制：硬件与任务双驱动

固定阈值 $\tau$ 无法兼顾复杂多变的推理环境。我们需要根据以下两个维度动态调整：

### A. 硬件开销感知（PCIe-Aware）

- **逻辑**：如果 PCIe 带宽低（如 PCIe 3.0 x8）或 CPU 验证延迟高，我们需要更长的 Draft 来掩盖开销，因此应**调低 $\tau$**（更容忍误差）。
- **公式**：$\tau_{hw} = \tau_{base} \cdot \frac{T_{verify}}{T_{verify} + T_{overhead\_pcie}}$。

### B. 任务语义感知（Task-Aware）

- **代码/数学生成**：对 Token 准确性极度敏感，微小的偏差会导致后续全错。可利用 **Logits 熵值** 监控：如果连续两个 Token 的 Top-1 概率 $P_{max} > 0.9$（代表处于确定性逻辑中），应**调高 $\tau$**。
- **创意写作**：多样性高，接受率天然较低，但也更容忍近似。可以通过前 $N$ 个 Token 的 **实际平均接受率** 动态在线修正 $\tau$。

## 一、 验证时机触发方案设计

在投机采样中，草稿长度 $K$ 的最优值取决于草稿模型与目标模型的“分布距离”。在你的场景下，这种距离是由“缺失的 CPU 专家”引起的。

### 1. 专家路由置信度方案 (Router-based Confidence)

这是最直接的方案，因为你跳过的是专家。

- **指标 1：Router Entropy (路由熵)**。如果路由器的输出分布非常平坦（熵高），说明模型对选择哪个专家犹豫不决，此时强行替换专家的风险极高。
- **指标 2：Expert Score Gap (分差指标)**。计算 $Score_{CPU\_Top1} - Score_{GPU\_Top1}$。如果原本该选的 CPU 专家分数远高于目前 GPU 上可用的专家，说明替换产生的偏差将迅速累积。
- **指标 3：Cumulative Replacement Error (累积替换率)**。记录当前序列中经过了多少个“非最优专家”层。错误会随深度和长度累积。

### 2. 输出分布特征方案 (Logit-based Metrics)

利用每一跳生成的 Logits 进行轻量化计算。

- **指标 4：Top-k Confidence & Entropy**。监控生成 Token 的置信度。
- **指标 5：Logit Distillation (蒸馏残差预估)**。如果 GPU 上的“残缺 MoE”在某一步生成的 Top-1 Token 概率突然大幅下降，通常意味着该 Token 严重依赖于被卸载的专家知识。

### 3. 隐状态偏移方案 (Hidden State Drift)

- **指标 6：Feature Norm / Variance**。当专家被跳过或替换时，Hidden State 的范数（Norm）往往会发生异常偏移。通过监控最后一层 Embedding 的变化率（与上一个 Token 的变化率对比）可以捕捉这种不稳定性。

### 4. 语义/结构感知方案 (Semantic Awareness)

- **指标 7：Token Type Trigger**。在 Reasoning 任务中，某些关键 Token（如 `Therefore`, `Step`, `+`, `=`, 数字）对准确率极度敏感。可以设定逻辑：一旦遇到特定逻辑引导词或符号，立即触发验证。

## 基于多维特征的启发式停止 (Multi-factor Heuristic Stopping)

我们建立一个评分函数 $S_t$，代表在第 $t$ 个草稿 Token 处的“置信度”。当 $S_t < \tau$（阈值）时，停止 Draft。

### 1. 专家偏差评价指标 (Expert Deviation Metrics)

这是针对你“CPU 专家替换”场景最关键的指标。

- 最大分数损失 ($L_{score}$)：

  在每一层 $l$ 中，如果 Top-1 专家 $e^*$ 在 CPU 上，而我们被迫使用了 GPU 上的专家 $\hat{e}$，则计算分差：

  

  $$L_{score}^{(t)} = \sum_{l=1}^{L} (RouterScore(e^*) - RouterScore(\hat{e}))$$

  

  逻辑： 分差越大，说明替换掉的专家越不可替代，模型偏离原始分布的可能性越高。

- 专家替换率 ($R_{sub}$)：

  统计该 Token 生成过程中，多少比例的层发生了专家替换。

  

  $$R_{sub}^{(t)} = \frac{\text{Count}(\text{Layer with CPU Experts})}{Total\_Layers}$$

### 2. 输出分布不确定性 (Output Uncertainty Metrics)

- 预测熵 (Entropy)：

  计算草稿模型输出 Logits 的熵 $H(P_t)$。

  

  $$H(P_t) = -\sum P(x) \log P(x)$$

  

  逻辑： 熵越高，表示模型对下一个 Token 的预测越不确定。在“残缺 MoE”中，高熵通常意味着关键知识位点的缺失。

- 置信度骤降 (Confidence Drop)：

  $P_{max}^{(t)} / P_{max}^{(t-1)}$。如果当前 Token 的最大概率远低于上一个 Token，说明模型进入了“胡言乱语”区。

## 二、 算法流程逻辑

### 算法：自适应 MoE 草稿停止 (Ada-MoE-Stop)

输入：当前草稿长度 $t$，阈值 $\tau$，衰减因子 $\gamma$

输出：是否继续 Draft (Boolean)

1. **初始化**：累积误差 $E_{total} = 0$。

2. **每一步 Draft 预测时**：

   - 计算当前 Token 在所有 MoE 层中的 **$L_{score}^{(t)}$**。

   - 计算当前 Logits 的 **Entropy $H_t$**。

   - 计算接受概率预估值 $\hat{P}_{acc}$：

     

     $$\hat{P}_{acc} = \exp( - (\alpha \cdot L_{score}^{(t)} + \beta \cdot H_t) )$$

     

     (其中 $\alpha, \beta$ 为权重超参数)

3. 动态窗口平滑：

   为了防止单层波动的误判，使用移动平均：$\bar{P}_{acc} = \gamma \cdot \bar{P}_{acc} + (1-\gamma) \cdot \hat{P}_{acc}$。

4. **决策**：

   - 如果 $\bar{P}_{acc} < \tau$ OR $t \ge Max\_K$：**停止 Draft，进入 Verify**。
   - 否则：**继续生成下一个 Draft Token**。



## 三、 实验参数与阈值设计

为了让这个方案落地，你需要针对不同的任务通过实验确定参数：

| **参数**                    | **建议初始值** | **调优方向**                                       |
| --------------------------- | -------------- | -------------------------------------------------- |
| **$\tau$ (停止阈值)**       | 0.7 - 0.8      | 若接受率低，调高 $\tau$；若加速比低，调低 $\tau$。 |
| **$\alpha$ (专家损失权重)** | 0.5            | 针对 MoE 密集任务（如代码、数学）需调高。          |
| **$\gamma$ (平滑系数)**     | 0.2            | 增大 $\gamma$ 会使停止决策更迟钝，减少验证次数。   |
| **Max K**                   | 8 - 16         | 视 PCIe 带宽而定，带宽越窄，K 应该越大。           |
